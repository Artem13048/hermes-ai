# Hermes.AI

**Hermes.AI** — чат-бот и мини-приложение в MAX для построения персональных городских маршрутов.

---

##  Назначение решения

**Проблема.** Житель или турист в незнакомом (или даже родном) городе тратит много времени на то, чтобы собрать маршрут: приходится искать места в разных источниках, сверять время работы, погоду, бюджет и расстояние между точками.

**Решение.** Hermes.AI собирает готовый маршрут за один диалог в мессенджере MAX. Бот учитывает интересы, время, бюджет, погоду и часы работы мест и сразу отдаёт результат: список точек, карту, ссылку на Яндекс.Карты и PDF.

**Ценность для пользователя:**
- не нужно переключаться между сайтами и приложениями;
- не нужно считать время и деньги вручную;
- можно выбрать места вручную через мини-приложение или доверить подбор AI.

---

##  Основной пользовательский сценарий

1. Пользователь открывает бота в MAX впервые.
2. Видит приветствие и кнопку **«/start»**.
3. Нажимает `/start` → выбирает город.
4. Указывает **время** прогулки (2–6 часов).
5. Указывает **бюджет** (бесплатно / до 500 / 1000 / 1500 / 3000 / без ограничений).
6. Выбирает **интересы** (категории: достопримечательности, музеи, парки, гастрономия, развлечения, религиозные объекты).
7. Бот строит маршрут, показывает:
   - список мест с адресами и ценами;
   - карту маршрута;
   - ссылку на Яндекс.Карты;
   - PDF для скачивания.
8. Пользователь может сохранить маршрут в профиль или построить новый.

**Дополнительно:** пользователь может написать боту свободным текстом («Хочу на 4 часа музеи и поесть, до 1500 ₽»), AI разберёт запрос и построит маршрут.

##  Состав и архитектура решения

### Компоненты

| Компонент | Файл | Назначение |
|---|---|---|
| Ядро бота | `app/bot_core.py` | Создание `Bot` и `Dispatcher` |
| Обработчики | `bot.py` | Логика `/start`, callback'ов, AI-запросов |
| Webhook + API | `api.py` | FastAPI: webhook для MAX + REST API для мини-приложения |
| Модели БД | `app/models.py` | `City`, `Place`, `Category`, `User`, `Route`, `SavedRoute`, `UserLike` |
| Подключение к БД | `app/database.py` | SQLAlchemy engine + SessionLocal |
| Сервисы | `services/` | Бизнес-логика: маршруты, AI, погода, расписание, экспорт, PDF, карты |
| Мини-приложение | `miniapp/index.html` | Веб-интерфейс для свайпов и сборки маршрута |
| Регистрация webhook | `setup_webhook.py` | Разовый скрипт для MAX API |

### Схема работы

```
MAX → webhook (api.py) → Dispatcher (app/bot_core.py) → bot.py
                                                          ↓
                                              services/* (логика)
                                                          ↓
                                                    PostgreSQL
```

### Стек

- **Python 3.11+**
- **FastAPI** — REST API + webhook
- **maxapi** — библиотека для MAX Bot API
- **SQLAlchemy** — ORM
- **PostgreSQL 15** — база данных
- **GigaChat** — AI-парсинг свободного текста
- **Яндекс.Карты (Static API)** — генерация карты маршрута
- **OpenWeatherMap** — погода
- **ReportLab** — генерация PDF

##  Одна команда для запуска всех локальных компонентов

```bash
docker compose up -d --build
```

После запуска:
- FastAPI доступен на `http://localhost:8000`
- PostgreSQL доступен на `localhost:5432`

## ️ Необходимые параметры окружения

Перед запуском создайте `.env` из шаблона:

```bash
cp .env.example .env
```

И заполните переменные:

| Переменная | Обязательна | Назначение |
|---|---|---|
| `MAX_BOT_TOKEN` | ✅ | Токен бота в MAX (получить в @MasterBot) |
| `MAX_WEBHOOK_SECRET` | ✅ | Секрет для webhook (5–256 символов) |
| `WEBHOOK_URL` | ✅ | Публичный HTTPS-адрес `/webhook` |
| `DATABASE_URL` | ✅ | Строка подключения к PostgreSQL |
| `ADMIN_IDS` | ✅ | ID администраторов через запятую |
| `GIGACHAT_CREDENTIALS` | ⚠️ | Ключ GigaChat (есть фолбэк на регулярные выражения) |
| `YANDEX_MAPS_API_KEY` | ⚠️ | Ключ Яндекс.Карт (карта опциональна) |
| `OPENWEATHER_API_KEY` | ⚠️ | Ключ OpenWeatherMap (погода опциональна) |
| `MAX_CA_BUNDLE` | ⚠️ | Путь к сертификатам Минцифры (по умолчанию `certificates.pem`) |
| `API_PORT` | ❌ | Порт FastAPI (по умолчанию 8000) |

Дополнительно положите в корень проекта файл **`certificates.pem`** — корневой и промежуточный сертификаты Минцифры, объединённые в один файл. Он нужен для работы MAX Bot API по HTTPS.

##  Описание работы с данными

### Модели БД

- **`City`** — город (id, name, region, country, координаты).
- **`Category`** — категория места (id, name). Фиксированный справочник: 1–6.
- **`Place`** — место (название, адрес, описание, цена, координаты, часы работы, рейтинг).
- **`User`** — пользователь MAX (max_user_id, выбранный город).
- **`Route`** — сохранённый маршрут (user_id, city_id, список мест).
- **`RoutePlace`** — связь маршрута и места (позиция, расстояние).
- **`SavedRoute`** — сохранённый маршрут пользователя (JSONB).
- **`UserLike`** — лайк места пользователем.

### Импорт данных

Данные о городах и местах загружаются через **админ-панель бота** (`/admin` → «Импорт JSON»):

1. Админ скачивает шаблон `data/template.json` и инструкцию `data/instructions.txt`.
2. Заполняет JSON.
3. Отправляет файл боту.
4. Бот парсит JSON и сохраняет данные в БД.

### Экспорт данных

Админ может выгрузить всю БД или один город через `/admin` → «Экспорт». Файл совместим с импортом — можно загрузить обратно.

##  Порядок работы с тестовыми данными

В репозитории есть готовые JSON-файлы с тестовыми данными для трёх городов: **Москва**, **Казань**, **Краснодар**.

### Как загрузить тестовые данные

1. Запустите бота и убедитесь, что вы в списке `ADMIN_IDS` (в `.env`).
2. Отправьте боту `/admin`.
3. Нажмите **«📥 Импорт JSON»** → **«📥 Скачать шаблон JSON»**, чтобы посмотреть формат.
4. Отправьте боту JSON-файл с данными (например, из папки `data/`).
5. Бот вернёт отчёт: сколько городов, категорий и мест добавлено/обновлено.

### Проверка, что данные загрузились

Отправьте `/admin` → **«📊 База данных»** → **«📊 Статистика»**. Увидите:
- количество городов,
- количество категорий,
- количество мест.

##  Пошаговый сценарий проверки

### 1. Запуск через Docker

```bash
# Клонировать репозиторий
git clone https://github.com/Artem13048/hermes-ai.git
cd hermes-ai

# Создать .env из шаблона и заполнить
cp .env.example .env

# Положить certificates.pem в корень
# (сертификаты Минцифры: корневой + промежуточный)

# Запустить
docker compose up -d --build

# Проверить логи
docker compose logs -f app
```

### 2. Проверка API

```bash
curl http://localhost:8000/
```

Ожидаемый ответ:
```json
{"status":"ok","service":"Hermes.AI API"}
```

### 3. Регистрация webhook

Webhook требует **публичный HTTPS**. Для локальной проверки используйте туннель (ngrok, cloudpub и т.п.):

```bash
# Пример с cloudpub (clo.exe)
./clo publish http 8000
```

Полученный URL подставьте в `.env`:
```env
WEBHOOK_URL=https://xxxx.cloudpub.ru/webhook
```

Перезапустите контейнер и зарегистрируйте webhook:

```bash
docker compose restart app
docker compose exec app python setup_webhook.py
```

### 4. Проверка бота в MAX

1. Откройте бота в MAX.
2. Нажмите **«Начать»** → должно прийти приветствие с кнопкой `/start`.
3. Нажмите `/start` → бот покажет список городов.
4. Выберите город → бот покажет главное меню.
5. Нажмите **«Построить маршрут»** → выберите время → бюджет → интересы.
6. Нажмите **«🚀 Построить маршрут»** → бот пришлёт маршрут, карту и ссылку.

### 5. Проверка БД

```bash
docker compose exec db psql -U hermes -d hermes -c "\dt"
```

Увидите список таблиц.

### 6. Остановка и повторный запуск

```bash
# Остановить (данные в БД сохранятся в volume)
docker compose down

# Запустить снова
docker compose up -d
```

Чтобы удалить и данные:

```bash
docker compose down -v
```

##  Известные ограничения

1. **Webhook требует HTTPS.** Для локальной отладки нужен туннель (ngrok, cloudpub и т.п.).
2. **AI (GigaChat) может быть недоступен.** В этом случае используется фолбэк на регулярные выражения — точность разбора ниже.
3. **Карты и погода работают только при наличии API-ключей.** Без них соответствующие функции отключаются.
4. **Статические данные о местах.** Бот не парсит сайты в реальном времени — данные загружаются админом вручную через JSON.
5. **Мини-приложение требует HTTPS** для работы внутри MAX.
6. **История маршрутов хранится в БД.** При удалении volume `postgres_data` история теряется.
7. **Сертификаты Минцифры обновляются.** Если MAX начнёт отдавать ошибки SSL, обновите `certificates.pem`.

##  Порядок остановки и повторного запуска решения

### Остановка

```bash
# Остановить контейнеры (данные сохранятся)

```

### Повторный запуск

```bash
# Запустить те же контейнеры
docker compose up -d
```

### Полная очистка (включая БД)

```bash
# Остановить и удалить volume с данными
docker compose down -v
```

### Обновление после изменения кода

```bash
# Пересобрать образ и перезапустить
docker compose up -d --build
```

### Просмотр логов

```bash
# Логи приложения
docker compose logs -f app

# Логи БД
docker compose logs -f db
```

### Перезапуск одного сервиса

```bash
docker compose restart app
```
